# Prompt: Brainstorming

适合需求不清、产品行为不确定、架构方向需要讨论、或者要把模糊想法变成可计划的 spec 时使用。这个 prompt 只做设计澄清，不改文件、不写实现代码。

```text
我想先 brainstorm，不要改代码。

想法 / 问题：

背景：

已知约束：

暂时不做：

请先读取必要上下文。如果现有项目事实会影响判断，先做只读 scout。

请按以下方式推进：
1. 先复述你理解的目标、约束和非目标。
2. 最多问 3 个会影响方向选择的关键问题。
3. 在信息足够时提出 2-3 个可行方案。
4. 每个方案说明核心思路、会影响哪些文件/模块、优点、风险、验证方式、是否适合分阶段。
5. 给出推荐方向，并明确推荐成立的前提。
6. 草拟验收标准和后续 reviewable slices。
7. 等我确认方向后，再进入 plan / TDD / 实现。
```
