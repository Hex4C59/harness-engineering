# Prompt: 概念知识调研

适合系统调研一个技术概念、知识主题、工程实践或研究方向，并把结果沉淀成可复用 Markdown 文档。

```text
我想系统调研一个技术概念或知识主题，不要改业务代码。

主题：

请围绕三部分调研：
1. 是什么：核心定义、关键术语、边界、容易混淆的概念。
2. 为什么：它解决什么问题、出现背景、适用场景、不适用场景、主要 trade-off。
3. 怎么做：实践步骤、最小例子、常见实现路径、验证方法、常见坑。

资料要求：
- 优先查论文、官方文档、技术报告、权威博客和一线工程实践文章。
- 区分事实、作者观点和你的推断。
- 每个关键结论都给来源链接或出处。
- 标注资料类型：paper / docs / technical report / blog / code / talk。
- 如果资料之间有冲突，列出冲突点和你更信哪一方，说明理由。

产物要求：
- 不要只在对话里回答；请把完整调研结果写成一个 Markdown 文件。
- 如果我没有指定路径，先建议一个路径，例如 `docs/research/YYYY-MM-DD-<topic>.md`。
- Markdown 文件需要包含：
  - 标题
  - 调研日期
  - 调研问题
  - 5 条以内核心结论
  - 是什么
  - 为什么
  - 怎么做
  - 关键概念和术语
  - 资料综述
  - 参考资料
  - 开放问题
  - 下一步建议
- 参考资料至少包含标题、作者或机构、发布日期、资料类型、链接和访问日期。
- 对话里只输出摘要、生成的文件路径、核心结论和仍需确认的问题。

最后请给出：
1. 5 条以内核心结论。
2. 最值得先读的 3 篇资料。
3. 如果要把这个主题用于项目，建议的最小实验或 reviewable slice。
```
