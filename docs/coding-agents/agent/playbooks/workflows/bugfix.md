# Workflow: Bug 修复

修 bug 时不要让 agent 直接“试着改”。必须先复现，再写失败回归测试，再最小修复。

## 标准流程

1. 读错误、日志和相关文档。
2. 稳定复现。
3. 找最近相关变更。
4. 在边界处加诊断或写最小复现测试。
5. 提出一个根因假设。
6. 用最小改动验证假设。
7. 写回归测试。
8. 修根因。
9. 跑完整验证。
10. 把失败模式写入 `docs/troubleshooting.md`。

可复制 prompt：[`../prompts/bugfix.md`](../prompts/bugfix.md)。

## 三次失败后停止

如果连续 3 次修复失败，停止继续打补丁，回到问题建模：

```text
是不是理解错需求？
是不是找错层？
是不是架构边界不对？
是不是测试夹具不可靠？
是不是外部依赖或环境问题？
```

不要让 agent 为了通过测试去改测试本身。先确认测试表达的是正确行为。
