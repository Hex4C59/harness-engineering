# 学习优先原则

陌生技术栈下使用 coding agent 的目标不是只拿到代码，而是得到自己能解释、能 review、能维护的代码。

核心原则：

```text
一次只学习一个概念。
一次只改变一个行为。
一次只接受自己能解释的 diff。
```

硬规则：

1. 不接受自己完全看不懂的核心 diff。
2. 陌生技术栈单次 diff 默认不超过 20-80 行。
3. 每轮只允许一个行为变化，不混入重构、换库、改名和格式化。
4. 每个新概念先看 tiny example，再进项目代码。
5. AI 的解释必须分成事实、推断和假设。
6. 独立 reviewer 只能辅助判断，不能替代你的最终理解。
7. 生产数据、权限、支付、认证、加密、`unsafe`、迁移和部署必须升级为高风险流程。

日常最小循环：

```text
Scout -> Slice -> Tiny Example -> Test -> Implement -> Check -> Review -> Reflection
```

每一轮结束都问：

```text
我能解释这个 diff 吗？
我知道它怎么验证吗？
我知道它坏了该从哪里查吗？
```
