# Reviewable Slices

核心判断：

```text
不可 review 的 diff = 未完成。
```

如果影响范围超过 2-3 个文件，或者会触碰公共接口、数据、权限、部署，就先拆成 reviewable slices。

每个 slice 必须满足：

- 只对应一个行为变化。
- 能单独测试或验证。
- diff 足够小，人工 5-10 分钟内能 review。
- 有明确回滚方式。
- 本轮只执行一个 slice，完成后停止等待 review。

## Blast Radius 问题

所有非平凡 Execution Plan 都先回答：

```text
这次改动对应哪个 Roadmap item？
是否已有 Spec？如果没有，意图和验收是否已经写清？
这次改动预计影响几个文件？
是否会改公共接口？
是否涉及数据迁移、权限、网络、部署或外部服务？
是否会引入新依赖？
如何测试？
如何回滚？
```

## Stop 条件

遇到这些情况要停下来重新拆分：

- diff 变大到无法 5-10 分钟 review。
- 本轮 slice 需要修改未预期文件。
- 需要引入新依赖。
- 需要改变公共接口、数据结构、权限或部署。
- 测试策略和计划不匹配。
- agent 开始顺手重构、改名或格式化无关文件。
