# Prompt: 技术栈选择

适合项目方向已经清楚，但技术栈还没定时使用。

```text
我要从零开始一个新项目，但技术栈还没有确定。请先帮我做技术栈选择，不要创建文件，不要写业务代码。

项目名称：
项目类型：
项目目标：
目标用户：
运行环境：比如 CLI / Web / 桌面 / 移动端 / 服务端 / 本地优先 / 云端部署
核心能力：
非目标：
个人偏好：
必须使用：
必须避免：
部署或发布方式：
性能要求：
数据存储要求：
安全或隐私要求：
团队规模：个人 / 小团队 / 公司项目
维护周期：一次性原型 / 长期维护

请输出：
1. 你需要我补充的关键问题；如果信息足够，请直接继续。
2. 2-3 个候选技术栈。
3. 每个候选的优点、风险、复杂度、测试方式、agent 协作友好度。
4. 推荐技术栈，以及推荐成立的前提。
5. 暂时不推荐的技术栈和原因。
6. 建议的最小项目结构。
7. 建议的初始化命令、测试命令、check 命令。
8. 建议写入 docs/decisions/ 的技术选型决策摘要。

请不要因为“流行”而推荐技术栈。优先考虑：简单、可测试、生态稳定、文档清楚、脚手架成熟、适合小步 TDD。
```
